# 6. Открытые вопросы ТЗ: принятые решения

Вопросы из раздела «Открытые вопросы» закрыты рабочими значениями по умолчанию,
чтобы разработку не пришлось останавливать. Каждое решение — параметр конфигурации,
и меняется без правки кода.

---

## 1. Автоответ — SMS, голос или и то, и другое?

**По умолчанию: и то, и другое** (`AUTOREPLY_MODE=both`).

Обоснование: голосовое сообщение слышит тот, кто дозвонился, но оно не оставляет
следа — SMS остаётся у клиента в телефоне вместе с вашим номером, и по нему проще
перезвонить. Вместе они закрывают оба случая.

Как изменить:

```env
AUTOREPLY_MODE=both   # голос + SMS (по умолчанию)
AUTOREPLY_MODE=voice  # только голосовое сообщение
AUTOREPLY_MODE=sms    # только SMS (звонок сбрасывается сразу)
AUTOREPLY_MODE=none   # без автоответа, но и без соединения
```

Что стоит учесть при выборе:

- **SMS платные** и тарифицируются по сегментам: русский текст на 200 символов —
  это 3 сообщения. Голос дешевле.
- **Голос требует записи файла** — синтеза произвольного текста у Zadarma нет.
- В режиме `sms` звонок завершается сразу, звонящий слышит короткие гудки —
  для части клиентов это выглядит как сбой связи.

## 2. Язык сообщения — узбекский или русский?

**По умолчанию: русский** (`AUTOREPLY_LANGUAGE=ru`), узбекский готов к включению
одной строкой (`AUTOREPLY_LANGUAGE=uz`). Оба текста — в [docs/03](03-autoreply-texts.md).

Практические соображения:

- Для **голоса** можно записать один двуязычный файл (сначала узбекский, потом русский) —
  вариант 3 в docs/03. Ограничение только по длительности: 20–25 секунд.
- Для **SMS** двуязычный текст обойдётся вдвое дороже. Узбекский латиницей дешевле
  русского: 160 символов в сегменте против 70.
- Встроенных голосовых фраз на узбекском у Zadarma нет — только записанный файл.

**Требуется решение владельца:** какой язык основной для рекламной кампании.

## 3. Нужно ли логировать все звонки для аналитики?

**Реализовано, включено по умолчанию** — вопрос дешевле закрыть сразу, чем добавлять
задним числом, когда данные за прошедшие месяцы уже потеряны.

Что пишется по каждому звонку: номер, время, решение системы и его причина, сколько
прошло с прошлого звонка, что именно было отправлено провайдеру, статус SMS,
а после разговора — длительность и результат (`answered`, `busy`, `no answer`…).

Доступ: `GET /admin/calls`, сводка — `GET /admin/stats` (см. [docs/05](05-api-and-extensions.md)).

Срок хранения — `CALL_LOG_RETENTION_DAYS` (по умолчанию 180 дней, `0` — хранить всё).
Таблица «номер → время последнего звонка» чисткой не затрагивается: она нужна для
работы логики и хранится бессрочно.

## 4. Нужна ли интеграция с существующей таблицей учёта лидов?

**Точка подключения готова, конкретная таблица — за владельцем.**

Достаточно указать `FORWARD_WEBHOOK_URL`, и каждое решение по звонку уходит POST-запросом
в формате JSON. Для Google Sheets в [docs/05](05-api-and-extensions.md) приведён готовый
скрипт Apps Script (5 строк) — интеграция занимает минут десять.

Тот же механизм подходит для amoCRM, Bitrix24, Make, Zapier, n8n.

**Требуется от владельца:** ссылка на таблицу учёта и то, какие колонки в ней нужны.

## Решения, принятые по умолчанию сверх ТЗ

Это места, где ТЗ оставляло свободу, а реализация требовала выбора.

| Решение | Как сделано | Почему |
|---|---|---|
| Звонок внутри окна тишины **не сдвигает** метку времени | `updateLastCallAt: false` для решения `ignore` | Иначе абонент, звонящий каждые 10 минут, никогда не смог бы дозвониться до владельца |
| Повтор внутри окна отдаётся штатному сценарию линии, а не сбрасывается | `REPEAT_CALL_ACTION=ignore` | ТЗ оставляет выбор реализации; сброс звонка выглядит для клиента как обрыв связи. Переключается на `hangup` |
| Скрытый номер обрабатывается штатным сценарием | Решение `unidentified` | По скрытому номеру нельзя вести историю, а слать автоответ «в никуда» бессмысленно |
| Один звонок — один автоответ даже при повторной доставке вебхука | Дедупликация по `pbx_call_id` | Провайдеры повторяют доставку при таймауте; без защиты клиент получил бы несколько SMS |
| Решение принимается по времени **сервера**, а не по полю `call_start` от АТС | `Date.now()` | `call_start` приходит в часовом поясе АТС без указания зоны; сравнивать его с сохранёнными метками рискованно |
| Подпись вебхука проверяется всегда в production | `ZADARMA_VERIFY_SIGNATURE=true` | Без проверки любой, кто знает адрес, мог бы перевести звонок на произвольный номер за ваш счёт |
| SMS отправляется **после** ответа провайдеру | Фоновая задача в `callFlow.js` | АТС ждёт ответ считаные секунды; отправка SMS в этот момент задержала бы обработку звонка |
| Номера в логах маскируются | `maskPhone()` | Логи хранятся дольше, чем нужно, и попадают в системы мониторинга |

## Что нужно от владельца для запуска

1. **Утвердить текст автоответа** и язык — [docs/03](03-autoreply-texts.md).
2. **Записать голосовой файл** (если выбран режим `voice` или `both`).
3. **Личный номер** для соединения «новых обращений» → `OWNER_PHONE`.
4. **Доступ к кабинету Zadarma** (или ключи API) — для настройки вебхука.
5. **Решение по SIM-карте**: условная переадресация (владелец сначала принимает
   звонки сам) или безусловная (все звонки сразу в систему) — [docs/02](02-sim-forwarding.md).
6. **Ссылка на таблицу учёта лидов**, если нужна интеграция.
