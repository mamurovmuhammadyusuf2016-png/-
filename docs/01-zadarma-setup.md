# 1. Подключение Zadarma и настройка вебхука

Инструкция для личного кабинета [my.zadarma.com](https://my.zadarma.com).
Порядок шагов важен: вебхук нельзя сохранить, пока сервис не поднят по HTTPS.

---

## Шаг 1. Виртуальный номер и АТС

1. **Пополните баланс** — без положительного баланса номер не подключить.
2. **Купите виртуальный номер**: «Виртуальные номера» → выберите страну/город → «Подключить».
   Подойдёт любой номер, клиенты его не увидят: на него будут переводиться звонки
   с вашей рекламной SIM-карты.
3. **Создайте АТС**: «Мои АТС» → «Создать АТС». Логика работает только через АТС,
   на «голом» номере вебхуков нет.
4. **Привяжите номер к АТС**: «Мои АТС» → «Входящие звонки» → выберите купленный номер
   → направьте его на сценарий АТС (внутренний номер или голосовое меню — что именно,
   зависит от шага 5).

## Шаг 2. Ключи API

1. Личный кабинет → **Настройки → API**.
2. Нажмите «Сгенерировать ключи», получите **ключ** и **секрет**.
3. Впишите их в `.env`:

```env
ZADARMA_API_KEY=ваш_ключ
ZADARMA_API_SECRET=ваш_секрет
```

Секрет используется дважды: им проверяется подпись входящих вебхуков и подписываются
запросы на отправку SMS. Секрет не должен попадать в репозиторий — только в `.env`
или в переменные окружения хостинга.

## Шаг 3. Голосовой файл автоответа

У Zadarma нет синтеза произвольного текста: доступны только заранее загруженные
аудиофайлы и набор стандартных фраз. Поэтому голосовой автоответ — это записанный файл.

1. Запишите файл с текстом из [docs/03-autoreply-texts.md](03-autoreply-texts.md).
   Формат: **WAV, 8 kHz, 16 bit, моно** (Zadarma принимает и mp3, но wav надёжнее).
2. «Мои АТС» → **Настройки → Аудиофайлы** (или «Звуковые файлы») → загрузите файл.
3. Скопируйте **ID файла** и укажите его в `.env`:

```env
AUTOREPLY_VOICE_FILE_ID=12345
```

> **Про узбекский язык.** Встроенные фразы Zadarma существуют только для
> ru, ua, en, es, pl, fr, de. Узбекский автоответ возможен двумя способами:
> записанным аудиофайлом (этот шаг) или через SMS — текст SMS может быть любым.

## Шаг 4. Запуск сервиса по HTTPS

Разверните сервис по инструкции [docs/04-deployment.md](04-deployment.md) и убедитесь,
что он доступен снаружи:

```bash
curl https://calls.example.com/health
# {"status":"ok","cooldownMinutes":40,...}
```

Zadarma принимает **только HTTPS** и проверяет адрес перед сохранением: присылает
`GET ...?zd_echo=<код>` и ждёт этот код обычным текстом в ответе. Сервис это умеет,
но должен быть запущен в момент сохранения настроек.

## Шаг 5. Адрес вебхука и типы уведомлений

**Вариант А — скриптом (быстрее):**

```bash
node scripts/zadarma-setup.mjs --url https://calls.example.com/zadarma/webhook
```

Скрипт проверит ключи, пропишет адрес и включит уведомления `notify_start` и `notify_end`.

**Вариант Б — вручную в кабинете:**

1. «Мои АТС» → **Настройки → Интеграции и API** (раздел «Уведомления о звонках»).
2. В поле URL укажите: `https://calls.example.com/zadarma/webhook`
3. Включите галочки:
   - **Начало входящего звонка (notify_start)** — обязательно, на нём построена вся логика;
   - **Окончание звонка (notify_end)** — для аналитики (длительность, результат);
   - остальные уведомления не нужны.
4. Сохраните. Если кабинет пишет об ошибке проверки — сервис недоступен по HTTPS
   или отвечает не тем кодом; проверьте `curl "https://calls.example.com/zadarma/webhook?zd_echo=test123"`,
   ответ должен быть ровно `test123`.

## Шаг 6. Куда соединять «новые обращения»

В `.env` укажите личный номер владельца:

```env
OWNER_PHONE=998901112233
```

Допустимы два варианта:

- **внешний номер** в международном формате без «+» — звонок уйдёт на мобильный
  (тарифицируется Zadarma как исходящий вызов, следите за балансом);
- **внутренний номер АТС** (например, `100`), если владелец пользуется SIP-приложением
  Zadarma — соединение бесплатное.

## Шаг 7. Проверка на живом звонке

1. Позвоните на **виртуальный номер Zadarma** с телефона, которого нет в базе.
   Ожидаемо: играет автоответ и/или приходит SMS, соединения с владельцем нет.
2. Позвоните с того же номера ещё раз через пару минут.
   Ожидаемо: ничего не происходит, повторного автоответа нет.
3. Проверьте журнал:

```bash
curl -H "Authorization: Bearer $ADMIN_TOKEN" https://calls.example.com/admin/calls
```

4. Чтобы не ждать 40 минут для проверки третьего сценария, временно поставьте окно в 1 минуту:

```bash
curl -X PUT -H "Authorization: Bearer $ADMIN_TOKEN" -H "Content-Type: application/json" \
     -d '{"cooldownMinutes": 1}' https://calls.example.com/admin/config
```

и верните обратно (`{"cooldownMinutes": 40}` или пустое тело `{}` — вернёт значение из `.env`).

### Что проверить отдельно на первом же звонке

Сервис отвечает АТС `{"ivr_play": "<файл>", "hangup": 1}` — «проиграть сообщение и положить трубку».
Убедитесь, что после сообщения звонок действительно завершается и **не переходит**
на внутренние номера сотрудников. Если в вашем сценарии АТС вызов всё же идёт дальше:

- поставьте `HANGUP_AFTER_AUTOREPLY=true` (значение по умолчанию), и
- в сценарии АТС сделайте destination по умолчанию для этого номера «голосовая почта»
  или несуществующий внутренний номер, чтобы после автоответа звонок никуда не уходил.

## Куда смотреть при проблемах

| Симптом | Причина и решение |
|---|---|
| Кабинет не сохраняет URL вебхука | Сервис не поднят / не HTTPS / не отвечает на `zd_echo`. Проверьте `curl` из шага 5 |
| В логах `Отклонён вебхук с неверной подписью` | `ZADARMA_API_SECRET` не совпадает с ключом, которым Zadarma подписывает уведомления. Перегенерируйте ключи и обновите `.env` |
| Звонок идёт по обычному сценарию, вебхук не приходит | Не включён `notify_start`, либо номер направлен мимо АТС |
| Автоответ не соединяет, но и не играет | Не указан `AUTOREPLY_VOICE_FILE_ID` или ID файла неверен. При `AUTOREPLY_MODE=sms` так и задумано |
| SMS не приходит | Проверьте баланс, `SMS_SENDER` (senderid должен быть согласован с Zadarma) и логи: статус пишется в поле `smsStatus` |
| Соединение с владельцем не проходит | Проверьте баланс и формат `OWNER_PHONE` (международный, без «+») |
