# Автообработка входящих звонков (Zadarma)

Backend, который принимает вебхук о входящем звонке и сам решает, что с ним делать,
исходя из того, звонил ли этот номер раньше и сколько времени прошло с прошлого звонка.

## Логика (главное требование)

| Ситуация | Что делает система | Метка времени |
|---|---|---|
| Номер звонит **впервые** | Автоответ (голосовое сообщение и/или SMS). С человеком **не соединяет** | сохраняется |
| Прошло **≥ 40 минут** с прошлого звонка | Это «новое обращение» — соединяет с личным номером владельца | обновляется |
| Прошло **< 40 минут** | Ничего: ни автоответа, ни соединения. Звонок идёт по штатному сценарию линии | **не** меняется |

Меню с выбором цифр (IVR 1-2-3) не используется — только логика по времени.

Порог 40 минут задаётся параметром `CALL_COOLDOWN_MINUTES` и меняется без правки кода,
в том числе на лету — запросом к `PUT /admin/config` (см. [docs/05](docs/05-api-and-extensions.md)).

> Почему звонок внутри окна тишины не сдвигает метку времени: иначе абонент, который
> звонит каждые 10 минут, бесконечно продлевал бы себе окно и никогда не смог бы
> дозвониться до владельца. Метка обновляется только при автоответе и при соединении.

## Что внутри

- **Node.js 22, ноль внешних зависимостей.** HTTP — встроенный `node:http`, база — встроенный
  `node:sqlite`, подписи — `node:crypto`. `npm install` не нужен, нечему ломаться при обновлении пакетов.
- **Проверка подписи вебхука** (`Signature`: `base64(HMAC-SHA1(caller_id + called_did + call_start, secret))`) —
  чужой запрос не сможет перевести звонок на произвольный номер.
- **Защита от повторной доставки** одного и того же вебхука по `pbx_call_id`: один звонок — один автоответ.
- **Журнал всех звонков** для аналитики: кто, когда, какое решение было принято, чем закончился разговор.
- **Точка расширения** для Google Sheets / CRM: `FORWARD_WEBHOOK_URL`.

## Быстрый старт

```bash
git clone <репозиторий> && cd zadarma-call-router
cp .env.example .env          # заполните OWNER_PHONE и ключи Zadarma
npm start                     # сервис поднимется на http://localhost:3000
```

Проверка логики без реальных звонков:

```bash
npm test                                            # 63 автотеста
node scripts/simulate-call.mjs --from 998901234567  # имитация входящего звонка
```

Первый вызов вернёт автоответ, повторный сразу — пустой ответ `{}` (игнор),
а после `PUT /admin/config {"cooldownMinutes": 0}` — соединение с владельцем.

## Как проходит звонок

```
Клиент звонит на рекламный номер (SIM)
        │
        │  условная переадресация (занято / не отвечает / недоступен)
        ▼
Виртуальный номер Zadarma ──► АТС Zadarma
        │
        │  POST /zadarma/webhook   event=NOTIFY_START
        ▼
   Этот сервис
        │  ищет номер в базе, сравнивает время с окном тишины
        ▼
   Ответ в JSON:
     первый звонок   -> {"ivr_play": "<файл>", "hangup": 1}   + SMS
     новое обращение -> {"redirect": "<номер владельца>", "return_timeout": 25}
     внутри окна     -> {}
```

## Структура проекта

```
src/
  config.js              конфигурация и её проверка при старте
  server.js              точка входа, запуск и остановка
  domain/
    decision.js          чистое правило «первый / новое обращение / игнор»
    messages.js          тексты автоответа (ru, uz)
  services/
    callFlow.js          оркестрация обработки вебхука
    responsePlan.js      перевод решения в JSON-ответ для АТС
    zadarmaClient.js     подписанные запросы к API (SMS, настройка вебхуков)
    settings.js          параметры, меняемые на лету (окно тишины)
    forwarder.js         отправка событий во внешнюю систему
  store/
    sqliteStore.js       номер -> время последнего звонка + журнал
    memoryStore.js       то же в памяти (тесты, отладка)
  http/
    app.js               маршруты: вебхук, /health, /admin/*
  lib/
    signature.js         подписи Zadarma (вебхуки и запросы к API)
    phone.js             нормализация номеров
scripts/
  zadarma-setup.mjs      настройка вебхука в кабинете Zadarma из консоли
  simulate-call.mjs      имитация входящего звонка
tests/                   автотесты (node --test)
```
