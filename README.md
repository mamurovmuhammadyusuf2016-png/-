# Jarvis — голосовой AI-агент для Android

Управляет телефоном голосом так же, как это делает человек: **смотрит на экран** через
Accessibility API, **нажимает, листает и печатает**, а **что именно делать — решает Groq**.

Это не набор из пяти заранее вшитых команд. «Открой Telegram» — просто тест. Работает
любое приложение, которое установлено на телефоне.

---

## Как это работает (в одну строку)

```
голос → SpeechRecognizer → текст → Groq (решает, что делать) → JSON-план
      → AccessibilityService (нажимает/печатает/листает) → TextToSpeech (отвечает голосом)
```

## 1. Скачать готовый APK (самый простой путь)

2. Нажми на последнюю зелёную сборку **Build APK**.
3. Внизу, в блоке **Artifacts**, скачай **`jarvis-debug-apk`**.

Нужен только JDK 17 и Android SDK (или Android Studio).

## 3. Установить на телефон

1. Скинь `app-debug.apk` на телефон (кабель, Telegram «Избранное», Google Drive — как удобно).
2. Открой файл в проводнике телефона.
3. Android спросит: *«Установка из неизвестных источников»* → **Разрешить**.
4. Нажми **Установить**.

Через `adb` (если телефон подключён к компьютеру):

```bash
adb install -r app-debug.apk
```

Нужен Android 8.0 и новее.

---

## 4. Дать разрешения

Открой приложение **Jarvis** и нажми по порядку:

1. **«Дать доступ к микрофону»** → *Разрешить*
   (на Android 13+ тут же спросит про уведомления → тоже *Разрешить*).
2. Вставь свой **Groq API key** в поле `GROQ_API_KEY` → **«Сохранить»**.
   Если ключ уже был зашит при сборке, поле заполнено автоматически.

---

## 5. Включить Accessibility Service ⚠️ самый важный шаг

Без этого Jarvis **не сможет нажимать кнопки**. Он только слушает — но ничего не делает.

1. В приложении нажми **«Включить Accessibility Service»**.
2. Откроются системные настройки → **Установленные приложения** (или *Скачанные сервисы*).
3. Выбери **Jarvis Agent**.
4. Переведи переключатель в положение **Вкл**.
5. Появится предупреждение «Разрешить Jarvis Agent полный контроль устройства?» → **Разрешить**.
6. Нажми «Назад» и вернись в Jarvis.

Вверху экрана должно быть:

```
✅ Микрофон
✅ Accessibility Service
```

> На Xiaomi/Redmi, Samsung, Huawei и Oppo Android иногда отключает такие сервисы, чтобы
> сэкономить батарею. Зайди в **Настройки → Приложения → Jarvis → Батарея** и поставь
> **«Без ограничений»**.

---

## 6. Запустить

1. Нажми **«Начать слушать»**.
2. В шторке появится уведомление *«Jarvis слушает»*.
3. Говори:

```
Jarvis, открой Telegram.
```

Слово **Jarvis** в начале обязательно (можно поменять в настройках или вообще выключить,
сняв галочку «Требовать слово активации»).

Внизу экрана — журнал: что услышал, что решил, что нажал.

## Первая проверка

Скажи по очереди:

| Команда | Что должно произойти |
|---|---|
| «Jarvis, открой Telegram.» | откроется Telegram |
| «Jarvis, открой Instagram.» | откроется Instagram |
| «Jarvis, открой Chrome.» | откроется Chrome |
| «Jarvis, открой ChatGPT.» | откроется ChatGPT |
| «Jarvis, открой настройки.» | откроются настройки телефона |
| «Jarvis, открой Telegram и напиши Мухаммадюсуфу: я опоздаю на пять минут.» | Telegram → поиск → чат → текст → **вопрос «Отправить?»** → отправка |

Последняя команда **спросит подтверждение** перед отправкой. Ответь голосом «да» или «нет»
(или нажми кнопку в появившемся окне).

Это только примеры. Работают и любые другие: «открой YouTube», «прокрути вниз», «назад»,
«найди кнопку сохранить», «открой Instagram и пролистай ленту».

### Проверка без голоса

Удобно для отладки — команды можно слать с компьютера:

```bash
adb shell am broadcast -a com.jarvis.agent.COMMAND --es text "открой Telegram"
adb shell am broadcast -a com.jarvis.agent.CONFIRM --ez approve true
```

Или просто ввести команду текстом в поле в самом приложении.

## REQUIRED API KEYS

Нужен **ровно один** ключ.

| Что | Ключ | Обязателен? | Зачем |
|---|---|---|---|
| **Groq** | `GROQ_API_KEY` | да, для «умных» команд | мозг: понимает команду и выбирает действия |
| Speech-to-Text | — | нет | Android `SpeechRecognizer`, встроенный |
| Text-to-Speech | — | нет | Android `TextToSpeech`, встроенный |
| Управление телефоном | — | нет | `AccessibilityService` |
| Чтение экрана | — | нет | Android Accessibility API |
| Жесты, нажатия, ввод текста | — | нет | Android Accessibility API |

Получить ключ: <https://console.groq.com/keys> (бесплатный тариф подходит).

**Куда вписать ключ — три способа (любой один):**

1. В самом приложении, поле `GROQ_API_KEY` → «Сохранить». *Проще всего.*
2. В файл `local.properties` перед сборкой: `GROQ_API_KEY=gsk_...` (файл в `.gitignore`).

> APK из GitHub Actions собирается **без ключа намеренно**: этот файл лежит в публичном
> релизе, а ключ внутри APK читается командой `strings` за секунду. Вписывайте ключ в
> приложении — он останется только на вашем телефоне.

**Какую модель выбрать.** По умолчанию `openai/gpt-oss-120b`, запасная `openai/gpt-oss-20b`.
Если модель отключили или упёрлись в лимит, Jarvis сам переходит к следующей. Кнопка
**«Какие модели есть»** в настройках спрашивает у Groq актуальный список и печатает его в
журнал — не нужно гадать.

**Без ключа приложение тоже работает** — но только на встроенных правилах: открыть
приложение, назад, домой, прокрутить, напечатать, найти элемент, отправить сообщение.
Сложные и нестандартные формулировки без Groq не разбираются.

> Ключ в APK можно вытащить из файла — это ограничение любого мобильного приложения.
> Для чего-то серьёзнее MVP поставь свой прокси и впиши его адрес в поле **API URL**:
> приложение пойдёт туда, а ключ останется на сервере.

## PERMISSIONS

Что запрашивает приложение и зачем:

| Разрешение | Зачем | Спрашивается |
|---|---|---|
| `RECORD_AUDIO` | слышать команды | всплывающим окном |
| `INTERNET` | запрос к Groq | автоматически |
| `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_MICROPHONE` | слушать в фоне | автоматически |
| `POST_NOTIFICATIONS` | уведомление «Jarvis слушает» | окном, Android 13+ |
| `QUERY_ALL_PACKAGES` | найти любое приложение по названию | автоматически |
| **`BIND_ACCESSIBILITY_SERVICE`** | **видеть экран и нажимать** | **вручную, в настройках** ← главное |

Что приложение **не** просит: контакты, SMS, камеру, геолокацию, файлы.

## Что реально работает

- 🎙 Постоянное прослушивание со словом активации, ответы голосом.
- 🚀 **Открыть любое приложение** по названию — включая русские названия, кривое
  распознавание и сокращения («телеграм», «инста», «чат гпт», «смс»).
- 👆 Нажатие на элемент по тексту, описанию или id — с автоматической прокруткой, если
  элемента не видно на экране.
- ⌨️ Ввод текста в поля (через Accessibility, с запасным вариантом через буфер обмена).
- 📜 Прокрутка в любую сторону, «Назад», «Домой», «Недавние», Enter.
- 🔍 Поиск элемента на экране с честным ответом «не нашёл».
- 🧩 **Многошаговые задачи**: открыть приложение → найти поле → напечатать → нажать.
- ✅ **Подтверждение перед необратимым**: отправка, удаление, покупка, звонок. Молчание =
  отказ, ничего не отправится.
- 🛑 Отмена голосом в любой момент.
- ♻️ **Восстановление**: если элемента нет — прокрутит, посмотрит снова, перепланирует
  задачу с учётом текущего экрана и только потом скажет, что не получилось.
- 🌐 Работает и без интернета (упрощённый режим на встроенных правилах).
- 🇷🇺🇬🇧 Русский и английский — и в командах, и в интерфейсе приложений.
- ⚡ Простые команды («открой Telegram», «назад», «прокрути вниз») выполняются **локально и
  мгновенно** — без запроса в сеть. Groq зовётся только когда правила не поняли.
- 🗣 После выполненной команды ~9 секунд можно говорить **без слова активации**.
- 🛑 «Стоп» останавливает план прямо во время выполнения.

## Известные ограничения Android

Это ограничения платформы, а не недоделки. Обходные пути указаны.

1. **Accessibility включается только руками.** Программно включить сервис нельзя —
   это защита Android. Поэтому шаг 5 обязателен.
2. **Нет настоящего «всегда слушаю».** `SpeechRecognizer` рассчитан на одну короткую фразу,
   поэтому Jarvis перезапускает его по кругу. Работает, но тратит батарею. Настоящий wake-word
   требует офлайн-движка (Porcupine/Vosk) — это следующий шаг, не MVP.
3. **Распознавание требует интернета** на большинстве телефонов (Google STT). Офлайн-пакет
   языка можно скачать в *Настройки → Google → Голосовой ввод → Распознавание офлайн*.
4. **Экраны с флагом `FLAG_SECURE`** (банки, Netflix, экран оплаты) не читаются и не
   нажимаются вообще. Так задумано в Android.
5. **Ввод текста** в часть приложений не проходит через `ACTION_SET_TEXT`; есть запасной
   путь через буфер обмена, но редкие кастомные поля ввода всё равно не поддаются.
6. **Enter в поле ввода** работает с Android 11+. На Android 8–10 вместо этого нужно нажимать
   кнопку «Отправить»/«Найти» на экране — планировщик так и делает.
7. **Производители убивают фоновые сервисы.** Xiaomi, Huawei, Oppo, Samsung. Лечится
   снятием ограничений батареи и автозапуском.
8. **Капчи, биометрия, системные диалоги разрешений** недоступны для автоматизации.
9. **Скорость.** Один шаг ≈ 0.7–1.5 с (ожидание отрисовки экрана) плюс ~1 с на ответ Groq.
   Команда из шести шагов занимает несколько секунд — это нормально.
10. **API-ключ внутри APK** извлекаем. Решение — прокси (см. выше).

## Что изменилось после первого тестирования на телефоне

Первая версия открывала Telegram, писала имя в поиск, **стирала его и писала туда же
сообщение**, а потом выходила. Разбор показал три независимые причины, и все исправлены:

1. **Нажатие считалось успешным, если жест просто отправлен системе.** `dispatchGesture`
   возвращает «принято к доставке», а не «кнопка нажата». Агент шёл дальше по плану и
   говорил «отправлено», когда ничего не произошло. Теперь ждём подтверждения жеста.
2. **Поле поиска выигрывало поиск элемента.** После ввода имени поле само содержит это имя
   и совпадает с целью лучше, чем строка чата. Теперь поле, куда только что печатали,
   исключается — и по идентификатору, и по совпадению текста.
3. **Модель не видела нужных элементов.** Дерево обходилось в ширину, и в описание экрана
   попадали контейнеры, а поле ввода и кнопка отправки обрезались. Теперь обход в глубину
   и отбор по важности: поля ввода и кнопки попадают в описание всегда.

Плюс: `Recognizer error 5` (колбэки TTS приходили не в том потоке), скорость (кэш экрана и
списка приложений, переиспользование соединения, мгновенные простые команды), подтверждение
решается по плану, а не по словам команды, и приёмник adb-команд закрыт от других приложений.

## Следующие улучшения

1. Офлайн wake-word (Porcupine / Vosk) вместо перезапуска `SpeechRecognizer` — меньше
   расхода батареи и мгновенная реакция.
2. Потоковый STT, чтобы Jarvis начинал думать ещё до конца фразы.
3. Скриншот + vision-модель как запасной вариант для экранов, которые Accessibility
   видит плохо (игры, Canvas, WebView).
4. Память о диалоге: «а теперь напиши ему же ещё раз».
5. Сценарии-макросы: «утро» = будильник + погода + первые непрочитанные.
6. Готовый прокси (Cloudflare Worker) в комплекте, чтобы ключ не жил в телефоне.
7. Подписанный release-APK и авто-обновление из GitHub Releases.
8. Instrumented-тесты на реальном эмуляторе поверх нынешних 15 сценариев.

## Структура проекта

```
app/src/main/java/com/jarvis/agent/
├── core/                     ← чистый Kotlin, без Android: всё покрыто тестами
│   ├── Actions.kt            план и список допустимых действий
│   ├── AgentLoop.kt          главный цикл: план → действие → проверка → восстановление
│   ├── AppMatcher.kt         «телеграм» → org.telegram.messenger
│   ├── ConfirmationPolicy.kt когда обязательно спросить «точно?»

│   ├── GroqPlanner.kt        мозг: Groq API
│   ├── Http.kt               HTTP без внешних библиотек
│   ├── MiniJson.kt           свой маленький JSON — одинаковый на телефоне и в тестах
│   ├── Phrases.kt            слово активации, «да/нет», «кому: что»
│   ├── PlanCodec.kt          JSON ↔ план
│   ├── Prompts.kt            промпт для модели
│   ├── RuleBasedPlanner.kt   офлайн-планировщик и страховка
│   └── Screen.kt             модель экрана и поиск элементов
└── android/                  ← всё, что трогает Android API
    ├── JarvisAccessibilityService.kt   глаза и руки
    ├── VoiceService.kt                 уши и рот
    ├── JarvisRuntime.kt                связывает всё вместе
    ├── ConfirmationBus.kt              «да/нет» из голоса или из окна
    ├── Speaker.kt                      TextToSpeech
    ├── Prefs.kt                        настройки
    ├── CommandReceiver.kt              команды через adb
    └── MainActivity.kt                 экран настройки
```

Смысл разделения: вся логика принятия решений лежит в `core/` и не знает про Android,
поэтому 15 сценариев из задания гоняются на обычной JVM за секунду — без эмулятора.

## Если что-то не работает

| Симптом | Причина | Что делать |
|---|---|---|
| Слышит, но ничего не нажимает | выключен Accessibility | шаг 5 |
| «Не понял команду» на сложных фразах | нет ключа Groq | вписать `GROQ_API_KEY` |
| Через минуту перестаёт слушать | система убила сервис | Батарея → «Без ограничений» |
| Молчит в ответ | нет голосового движка | *Настройки → Язык → Синтез речи* |
| В журнале `Recognizer error 5` | см. раздел ниже | ↓ |
| Нажал, а ничего не произошло | элемент не нажался | Jarvis теперь это замечает и говорит вслух; посмотрите журнал |
| Не нашёл приложение | другое название в системе | скажи название так, как оно на экране |
| Не отправляет сообщение | не ответил на подтверждение | скажи «да» в течение 25 секунд |

Что именно произошло — всегда видно в журнале внизу главного экрана.

### `Recognizer error 5` (ERROR_CLIENT)

Это ответ системной службы распознавания: «не могу начать сессию». Само приложение при
этом живо — оно просто не получает текст. По порядку:

1. **Проверь, кто отвечает за голосовой ввод.**
   *Настройки → Приложения → Приложения по умолчанию → Помощник и голосовой ввод* (на
   Xiaomi/Samsung путь может называться *Цифровой помощник* или *Голосовой ввод*).
   Должно стоять **Google**. Если стоит ассистент производителя (Bixby, Xiaomi AI) —
   переключи на Google.
2. **Приложение Google должно быть включено и обновлено.**
   *Настройки → Приложения → Google → Включить*, затем обновить в Play Маркете.
   На телефонах без сервисов Google (HarmonyOS, некоторые китайские прошивки)
   `SpeechRecognizer` может отсутствовать вовсе — тогда голос работать не будет,
   но команды текстом в приложении и через `adb` работают.
3. **Дай приложению Google доступ к микрофону** — распознавание идёт через него.
4. **Включи «Офлайн-распознавание»** в настройках Jarvis и скачай языковой пакет:
   *Настройки → Google → Голосовой ввод → Распознавание речи офлайн → Русский*.
5. **Сними ограничения батареи** для Jarvis (*Настройки → Приложения → Jarvis → Батарея →
   Без ограничений*) — система может обрывать сессии в фоне.
6. **Закрой другие приложения, держащие микрофон** (диктофон, звонок, Zoom).

Jarvis сам пересоздаёт распознаватель после каждой такой ошибки и увеличивает паузу
между попытками (0.6 с → 1.2 с → 2.4 с … до 30 с), поэтому цикл не «захлёбывается».
После четырёх неудач подряд он один раз скажет об этом вслух и напишет подсказку в журнал.
